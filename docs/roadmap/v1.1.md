# Roadmap: v1.1, the desktop evolution

The order to refine and build the desktop evolution's remaining tickets in. Phases 1 and 2 and the first three steps of
phase 3 are built, and steps keep their original numbers. The decisions behind it are on the
[#104](https://github.com/maxenceng/lazyclaude/issues/104) map, and the phases are its *Destination*'s.

Refine each ticket just before it is built (`/ticket refine <number>`, one per session), not the whole list up front:
its *Model decision* depends on the code already there. Issue numbers don't give the order; this list does. Every phase
is Linux x86_64 only (ADR 0056).

## 3. GitHub Issues as the tracker

One cut-over, for the claude-tools harness and every project (ADR 0052–0055).

11. [#126](https://github.com/maxenceng/lazyclaude/issues/126): lazyclaude's own backlog moves to Issues, and this roadmap to
    `docs/roadmap/` (ADR 0068). From this step on, a ticket is named by its issue number.
12. [#77](https://github.com/maxenceng/lazyclaude/issues/77): `c` on the Board captures a draft ticket as a new issue.

## 4. MkDocs for every other doc

This phase depends on none of the first three, so it can be built earlier.

13. [#85](https://github.com/maxenceng/lazyclaude/issues/85): the docs build on Zensical, pinned, `make docs` strict in `verify`.
14. [#86](https://github.com/maxenceng/lazyclaude/issues/86): `make adr-index`, checked stale by `adr-check`.
15. [#87](https://github.com/maxenceng/lazyclaude/issues/87): the Docs panel orders documents as the site does.

The spring-ddd template's share of the docs build is in claude-tools' own backlog.

## 5. A sidecar backend

Its hosted sessions rest on phase 1's, which are built (ADR 0050).

16. [#155](https://github.com/maxenceng/lazyclaude/issues/155): `lazyclaude --sidecar` answers the board over JSON Lines.
17. [#156](https://github.com/maxenceng/lazyclaude/issues/156): the protocol schema is generated from the
    Views and drift-checked.
18. [#157](https://github.com/maxenceng/lazyclaude/issues/157): hosted sessions over the sidecar, `session/repaint`
    included.
19. [#158](https://github.com/maxenceng/lazyclaude/issues/158): docs and review over the sidecar.

## 6. The desktop frontend and its packaging

20. [#78](https://github.com/maxenceng/lazyclaude/issues/78): `frontend/`, the relay, the protocol client and

## 7. The desktop window, day to day

What using the desktop window for real turned up. Only step 26 has to come first: a ticket's session that Claude Code
cannot run blocks the `/ticket` loop, so it can go before [#82](https://github.com/maxenceng/lazyclaude/issues/82).
The rest need nothing from steps 24 and 25.

26. [#182](https://github.com/maxenceng/lazyclaude/issues/182): a ticket's new session runs `/ticket` under the
    plugin's name, so Claude Code knows the command. A fix, reproduced first.
27. [#183](https://github.com/maxenceng/lazyclaude/issues/183): `config.yml` sets the ticket plugin's name and the
    verbs each status offers, read by both frontends. Step 26 may land the plugin name first.
28. [#184](https://github.com/maxenceng/lazyclaude/issues/184): a Configuration button edits `config.yml`, the
    first write that is not to GitHub, so it needs an ADR. Needs step 27.
29. [#187](https://github.com/maxenceng/lazyclaude/issues/187): tabs switch the window between the base view, the
    Issues board as status columns (the TUI's zoomed Board) and the open pull requests. Likely split at refine.
30. [#188](https://github.com/maxenceng/lazyclaude/issues/188): a click on a status line lamp or count goes to its
    session.
31. [#186](https://github.com/maxenceng/lazyclaude/issues/186): a shown document closes, and the dock minimises to
    its tabs.
32. [#185](https://github.com/maxenceng/lazyclaude/issues/185): the panes resize by dragging their seams. After
    steps 29 and 31, which change what the grid holds.
33. [#189](https://github.com/maxenceng/lazyclaude/issues/189): Markdown stays readable on a large screen.
